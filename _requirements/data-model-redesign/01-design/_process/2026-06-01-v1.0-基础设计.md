# 过程：v1.0 基础设计

> 日期：2026-06-01
> 触发原因：0006 文档从无到有，首次梳理数据模型与界面重构方案
> 影响范围：0006 文档 §一 ~ §九、22 张表（v1.0 时 16 张）、3 大领域划分

---

## 调整内容

- 新增 0006 文档（v1.0 版本）
- 建立 3 大基础领域划分：
  - 领域 1：合约行情（4 张表：futures_contracts / futures_quotes / futures_daily / futures_min）
  - 领域 2：策略（4 张表：strategies / strategy_param_history / strategy_signals / strategy_signal_states）
  - 领域 3：交易 / 账户（8 张表：trade_sessions / sim_account / sim_orders / sim_trades / sim_positions / position_units / sim_event_log / live_*）
- 建立 5 个界面 Tab（信号/模拟/真实/回测/账户）
- 引入 `strategies/<type>/V<N>/strategy.py` 多版本代码组织
- 建立 22 个 API（含 4 个重定向）

## 关键决策

| # | 决策 | 备选 | 决定理由 |
|---|------|------|---------|
| 1 | 3 大基础领域划分 | 单领域混合 | 解耦策略与交易，状态属于交易事实 |
| 2 | v1.0 表数 16 张 | 精简版（10 张）| 避免早期过度设计，但保留 live_* 预留 |
| 3 | 多版本代码组织（`strategies/<type>/V<N>/strategy.py`）| 单一路径 | 海龟 V1 / V2 共存，支持参数迭代追溯 |
| 4 | 引入 trade_sessions 主表 | 直接在 sim_orders 上 | Session 是完整交易生命周期（建仓→平仓）的合适抽象 |
| 5 | strategy_signal_states 独立表 | 信号主表加状态字段 | v1.0 独立，v1.3 决定删除（派生数据不持久化）|
| 6 | live_orders / live_trades / live_positions 预留 | 不预留 | Phase 7 接入 CTP 必用 |
